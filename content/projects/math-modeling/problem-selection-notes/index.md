## A题：水泥电除尘器协同优化控制

### 题目本质

这是一个典型的：

```text
工业过程建模 + 工况聚类 + 约束优化 + 能耗分析
```

它要求分析入口温度、流量、入口浓度、电压、振打周期与出口粉尘浓度之间的关系，然后在排放约束下最小化电耗。

附件数据是：

```text
Cement_ESP_Data.csv
```

我检查到它有：

```text
10080 行
分钟级数据
连续 7 天
字段包括：
Temp_C
C_in_gNm3
Q_Nm3h
U1_kV ~ U4_kV
T1_s ~ T4_s
C_out_mgNm3
P_total_kW
```

### 优点

A题很适合用你现在搭好的 Codex/OMX 工作流：

```text
数据预处理
特征工程
随机森林 / XGBoost / LightGBM
SHAP 或特征重要性
KMeans 工况划分
约束优化
敏感性分析
```

论文也容易写出工程感。

### 关键风险

这个题有一个明显问题：题目要求保证出口粉尘浓度：

```text
C_out ≤ 10 mg/Nm³
```

并且问题4还要求分析从：

```text
10 mg/Nm³ 下调到 5 mg/Nm³
```

但附件数据里的 `C_out_mgNm3` 基本在：

```text
48.74 ~ 50.00 mg/Nm³
```

也就是说，**历史数据几乎没有覆盖 10 mg/Nm³ 以下的运行状态**。这会导致问题2、问题4需要明显外推，模型可信度会受影响。

### 适合什么队伍？

如果你们队伍擅长机器学习、工业数据分析、优化算法，可以做。
但如果比赛时间紧，我不建议首选 A，因为它有“数据目标不一致”的坑。

## B题：多源融合机器人定位及任务优化

### 题目本质

这是一个非常标准、非常适合数学建模比赛的题：

```text
时间对齐 + 多传感器融合 + 偏差估计 + 轨迹重建 + 任务优化
```

四问递进关系很清楚：

```text
问题1：无噪声数据，对齐时间，生成 10Hz 轨迹
问题2：有噪声和系统偏差，估计时间偏差和系统偏差，融合轨迹
问题3：实际数据，判断是否有系统偏差，再完成融合
问题4：基于轨迹完成射击/拍照任务优化，填 result.xlsx
```

### 附件情况

B题附件很完整：

```text
附件1.xlsx    无噪声两类定位数据
附件2.xlsx    有噪声 + 系统偏差数据
附件3.xlsx    实际测量数据
附件4.xlsx    射击目标和拍照目标
result.xlsx   最终填写结果模板
```

我检查到：

```text
附件1：
方式1 约 3000 行，4Hz
方式2 约 4000 行，5Hz

附件2：
方式1 约 3000 行
方式2 约 3948 行

附件3：
方式1 约 1381 行
方式2 约 1621 行

附件4：
射击目标 18 个
拍照目标 18 个
```

### 优点

B题最大优点是：**问题闭环非常完整。**

你可以从第一问一路写到第四问，每一步都有明确输出：

```text
时间偏差
系统偏差
10Hz 融合轨迹
速度/加速度曲线
目标任务完成表
result.xlsx
```

而且图很好画：

```text
两传感器原始轨迹对比图
时间对齐前后轨迹图
融合轨迹图
误差曲线
速度/加速度曲线
任务目标分布图
最终执行点可视化
```

这些图放进论文非常加分。

### 推荐模型路线

#### 问题1

```text
插值重采样
轨迹相似度匹配
时间偏差搜索
最小均方误差 MSE
10Hz 轨迹生成
```

#### 问题2

```text
时间偏差估计
系统偏差估计
加权融合
卡尔曼滤波 / 平滑滤波
10Hz 轨迹输出
```

#### 问题3

```text
先判断系统偏差是否显著
再做融合
用残差均值、置信区间、轨迹差分判断
```

#### 问题4

```text
轨迹重采样到 10Hz
计算速度 v 和加速度 a
筛选满足约束的候选执行点
射击任务：距离 5~30m，v≤2m/s，a≤1.5m/s²，提前 1.5s 满足约束
拍照任务：距离 10~40m，角度差至少 60°，v≤1.5m/s，a≤1.5m/s²，提前 0.5s 满足约束
贪心 / 动态规划 / 多目标优化
填写 result.xlsx
```

### 风险

B题也有难点，主要是问题4：

```text
任务选择和时序安排比较细
result.xlsx 不能改红色文字
需要严格检查速度、加速度、准备时间约束
```

但这些难点是“工程可控”的，不是“题目本身不清楚”。

### 我的评价

B题是三道题里最适合你们的。
尤其你已经搭好了：

```text
Codex CLI
Oh My Codex
math-modeling-router
math-modeling-executor
math-modeling-paper-reviewer
docx-editor-cn
```

B题可以充分发挥自动写代码、跑数据、画图、生成论文的优势。

## C题：氦气产业链优化

### 题目本质

这是一个：

```text
供应链优化 + 风险建模 + 战略规划
```

它要求做 2027 年氦气采购、运输、运营方案，还要考虑地缘政治风险、断供、出口管制、国内增产、进口多元化、回收、战略储备等。

附件数据包含很多 sheet：

```text
提氦成本
氦气进口价格
运输路线
氦气消费量
氦气产量
氦气海关进口数据
需求量与产量
生产模式和生产最大能力
GPR 地缘政治风险指数
GPR_HISTORICAL
GPR_COUNTRIES
GPR_WORDS
```

### 优点

C题论文空间大，适合写：

```text
线性规划
多目标优化
鲁棒优化
风险加权模型
供应安全指数
情景分析
战略建议
```

如果写得好，会很像政策咨询报告。

### 关键风险

C题的问题是：

```text
数据杂
口径不统一
单位转换复杂
缺失较多
需要外部资料
主观假设多
结果难验证
```

我还注意到附件里有一个：

```text
氦气市场价格
```

sheet 基本是空的。

而题目又说：

```text
基于附件数据，但不限于这些数据
```

这意味着你们大概率需要自己补外部数据。这样做的风险是：
**最后容易变成“查资料 + 讲政策 + 编指标”，模型不够硬。**

### 适合什么队伍？

如果你们队伍有人擅长经济、供应链、政策分析、论文写作，可以考虑。
但如果你们想稳妥完成代码、数据、图表、结果，我不建议选 C。

## 我的最终建议

### 首选：B题

原因：

```text
1. 数据最完整
2. 四问递进最清楚
3. 代码实现路径明确
4. 结果容易验证
5. 图表容易做
6. 论文结构好写
7. 最适合 Codex/OMX 自动化工作流
```

### 备选：A题

如果你们更想做工业优化题，可以选 A。
但要提前解决一个核心问题：

```text
历史数据 C_out 接近 50 mg/Nm³，
而题目约束是 10 mg/Nm³ 和 5 mg/Nm³。
```

这个需要在论文里解释清楚，否则容易被质疑。

### 不优先选：C题

C题不是不能做，而是更吃资料、假设和宏观叙事。
如果时间短，它最容易写虚。
